"# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ ИНТЕГРАЦИИ ФУНКЦИИ ИНТЕРАКТИВНЫХ РАЗМЕРОВ (INPUT OVER CANVAS)

## Контекст задачи
Мы разрабатываем специализированный оконно-фасадный конфигуратор на TypeScript и React. 
Данные геометрии хранятся в виде Графа (светопрозрачные конструкции: стойки, ригели, рамы). 
Координаты в стейте хранятся в реальных миллиметрах (инженерное пространство), а на холсте (Canvas/Konva) отображаются с учетом коэффициента масштабирования (Zoom) и смещения (Pan).

## Цель
Реализовать систему автоматического образмеривания и позиционирования горизонтального ригеля (или вертикальной стойки) относительно соседних профилей через интерактивные HTML-инпуты, абсолютно спозиционированные поверх холста. При изменении значения в инпуте линия должна точно менять свою координату.

## Спецификация алгоритма и математики

1. **Функция поиска смежных границ (`findBoundaries`):**
   * При выборе горизонтальной линии (ригеля) с координатой `currentY`, алгоритм должен найти в массиве всех горизонтальных линий (`allHorizontalY`) две ближайшие координаты: 
     * `topY` (ближайшая линия сверху, у которой Y меньше `currentY`).
     * `bottomY` (ближайшая линия снизу, у которой Y больше `currentY`).
   * Если выбран вертикальный импост (`currentX`), аналогично искать `leftX` и `rightX` в массиве `allVerticalX`.

2. **Функции трансформации координат (Важно!):**
   * Необходимо реализовать/использовать чистые функции перевода координат из CAD-пространства (мм) в экранные пиксели (px):
     * `toScreenX(cadX: number, panX: number, zoom: number): number` -> `(cadX * zoom) + panX`
     * `toScreenY(cadY: number, panY: number, zoom: number): number` -> `(cadY * zoom) + panY`
   * И обратные функции для сохранения измененных данных из инпута обратно в модель: `toCadX`, `toCadY`.

3. **Интерфейс ввода (UI Overlay):**
   * Инпуты не должны рисоваться внутри Canvas. Они рендерятся как стандартные HTML `<input type="number" />` в абсолютно позиционированном контейнере (`position: absolute`) поверх холста.
   * **Позиционирование инпута "До верха":** Должен располагаться строго по центру отрезка между `topY` и `currentY` по вертикали, и по центру самого ригеля по горизонтали.
   * **Позиционирование инпута "До низа":** Должен располагаться строго по центру отрезка между `currentY` и `bottomY` по вертикали.

4. **Логика обновления данных (State Mutation):**
   * При изменении инпута "До верха" (значение `dTop`), новое положение линии рассчитывается как: `newY = topY + dTop`.
   * При изменении инпута "До низа" (значение `dBottom`), новое положение линии рассчитывается как: `newY = bottomY - dBottom`.
   * При вводе значения срабатывает callback `onLineUpdate(lineId, newCoordinate)`. 
   * Должна быть валидация: `newY` не может быть меньше `topY + минимальный_проем` и не может быть больше `bottomY - минимальный_проем` (например, не менее 100 мм на проем).

## Требования к коду и оформлению
* **Язык:** TypeScript (строгая типизация всех интерфейсов, никаких `any`).
* **Компоненты:** React (функциональные компоненты, хуки `useMemo` для тяжелых расчетов границ, чтобы не пересчитывать их на каждый микро-сдвиг мыши).
* **Стилизация:** Инпуты должны иметь аккуратный минималистичный инженерный вид (без дефолтных стрелочек браузера Chrome/Firefox, полупрозрачный фон, фокус по клику, автовыделение текста при фокусе `e.target.select
()`).
* **Обработка событий:** При нажатии `Enter` или потере фокуса (`onBlur`) фиксировать изменения. При нажатии `Escape` — сбрасывать ввод к текущему честному значению геометрии.
