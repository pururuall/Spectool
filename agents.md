# AGENT.MD — Руководство по архитектуре и разработке Spectool

Этот документ предназначен для AI-агентов и разработчиков, работающих над кодовой базой **Spectool**. Он описывает предметную область, архитектурные решения, структуру проекта, алгоритмы и правила внесения изменений.

---

## 1. О проекте (Domain & Purpose)

**Spectool** — специализированный инженерный 2D CAD/BIM-конструктор для проектирования модульных светопрозрачных и глухих фасадов, формирования производственных спецификаций (BOM — Bill of Materials) и автоматической выгрузки ведомостей в Excel по отраслевому заводскому эталону (**«Модуль Жукова» / А1187 М507**).

### Ключевые возможности:
1. **Интерактивный CAD-холст:** черчение осевых линий стоек и ригелей, магнитные привязки, режим ORTHO, перетаскивание узлов, масштабирование и панорамирование.
2. **Алгоритм детекции контуров (`cellDetector.ts`):** автоматический поиск замкнутых прямоугольных областей (проёмов/полей) в любой сетке профилей (включая Т-образные врезки и асимметричные деления).
3. **Универсальные заполнения проёмов:** привязка стеклопакетов, коробов утепления с развертками, вентрешеток, створок и сэндвич-панелей с настраиваемыми отступами и шаблонами.
4. **Управление комплектацией и метизами:** ручная или полуавтоматическая привязка крепежа (винты, болты, заклепки) и уплотнителей/термовставок к профилям и ячейкам с формулами расчёта шага.
5. **BOM-движок спецификаций (`bomEngine.ts`):** расчёт 19-колоночной производственной таблицы (размеры хлыстов, заготовок, площади, веса) и генерация форматированного `.xlsx` с формулами и цветовой кодировкой (зелёные детали, синие комплектующие).
6. **Автономный Portable Desktop Client:** сборка на Electron в один `.exe` файл без сторонних зависимостей.

## 2. Стек технологий

- **Фронтенд:** React 19, TypeScript 5.7, Vite 6.
- **Стилизация:** Tailwind CSS v4, Lucide React (иконки).
- **Работа с Excel:** `exceljs` (генерация форматированных файлов спецификаций с ячейками и стилями), `xlsx` (чтение и парсинг баз данных).
- **Десктопная платформа:** Electron 45, `electron-builder` (сборка `target: portable`).
- **Тестирование и автоматизация:** `puppeteer-core` (Headless Chrome E2E-проверки холста и CAD-инструментов).

## 4. Ключевые архитектурные сущности и данные

### 4.1. Линия (`Line`)
Осевая линия несущего металлокаркаса:
- `start: { x, y }`, `end: { x, y }` — координаты в миллиметрах реального масштаба.
- `profile`: привязанный профиль (стойка, ригель, рама, прижимная планка).
- `dependencies`: массив привязанных метизов и уплотнителей с формулами расчёта количества (`fixed`, `step`, `formula`).
- `lengthFormula`: формула длины заготовки (например, `H - 60` для вертикалей или `W - 50` для горизонталей).

### 4.2. Ячейка / Область (`Cell`)
Замкнутый светопрозрачный или глухой проём, ограниченный линиями:
- `polygon`: массив вершин четырёхугольника `[{x, y}, ...]`.
- `width`, `height`: осевые габариты проёма.
- `fillType`: тип связи (`"part"` — деталь, `"assembly"` — сборочная единица, `"accessory"` — комплектующие).
- `hasMaterial`: флаг, привязан ли листовой материал (например, для стеклопакета `false`, для короба оцинковки `true`).
- `cutWidthFormula`, `cutHeightFormula`: формулы габаритов развертки/заготовки (например, `W - 25`, `H - 25` для стеклопакета или `W + 160`, `H + 160` для короба).
- `assignedMaterial`: название материала и толщина/плотность.
- `dependencies`: метизы/комплектующие, привязанные к проёму.

### 4.3. Алгоритм детекции областей (`cellDetector.ts`)
Использует метод интервального анализа лучей:
1. Находит все X-координаты вертикалей и Y-координаты горизонталей.
2. Проверяет каждый прямоугольный сектор `[x1, x2] × [y1, y2]` на покрытие 4 граничными отрезками.
3. Проверяет отсутствие секущих внутренних профилей, делящих сектор пополам.
4. Корректно находит ячейки в несимметричных и Т-образных фасадах (например, 3-секционный фасад Жукова с нижним поясом).

### 4.4. Стандарт наименований и порядковых номеров профилей («палок») (`namingService.ts`, `NamingFormulaModal.tsx`)
Марки деталей формируются по настраиваемому шаблону формулы. Доступны отраслевые стандарты:
- **По длине по осям:** `{project} {article}-{axialLength}-{order}` (например, `А1187 0101-2555-1`)
- **По фактической длине (с подрезкой):** `{project} {article}-{cutLength}-{order}` (например, `А1187 0101-2515-1`)
- **Сплошной дефис:** `{project}-{article}-{cutLength}-{order}` (например, `А1187-0101-2515-1`)
- **Без порядкового номера:** `{project} {article}-{cutLength}`
- **Порядковые номера:** по умолчанию назначаются последовательно `1, 2, 3...`, с возможностью ручного редактирования в таблице `№ Палок` или сброса в один клик.

### 4.5. Мульти-цветовая система фасада (`ColorManagerPopover.tsx`)
Фасадные модули часто содержат профили разных оттенков (например, несущий каркас `RAL 7012`, а декоративные крышки и прижимы `RAL 9005` или `RAL 9006`).
- В шапке доступен менеджер цветов проекта.
- В `ParametersBox` при привязке или редактировании профиля инженер в один клик выбирает цвет из палитры проекта или вводит любой произвольный оттенок.

### 4.6. Независимые детали и сборочные единицы (Кронштейны, закладные) (`StandaloneItemModal.tsx`)
Фасадный модуль включает элементы, не наносимые осевыми линиями на 2D-чертеже (кронштейны опорные/ветровые, закладные детали, анкеры, сварные сборочные единицы):
- Сущность `StandaloneItem` добавляется в спецификацию кнопкой `+ Деталь / СБ`.
- Для детали указываются: габариты $L$, $B$, $K$, материал, шаблон ТП, количество, покрытие и примечание.
- Для сборочной единицы: наименование, обозначение чертежа, шаблон ТП (напр. «Кронштейны сварные/сборные модульные»), количество.
- Полная интеграция в 19-колоночную спецификацию и экспорт в Excel/Vogbit.

### 4.7. База данных шаблонов техпроцесса (ТП для Vogbit) (`ProcessTemplatesModal.tsx`, `processTemplatesService.ts`)
- Включает 27 заводских технологических категорий по отраслевому классификатору («Типы деталей в производстве.xlsx»).
- Инженер может добавлять свои шаблоны ТП, редактировать или удалять их. Сохраняются персистентно в `localStorage`.
- Позволяет системе Vogbit автоматически формировать номенклатурные позиции и технологические карты при импорте спецификации.

### 4.8. Импорт спецификации и управление проектами (`excelImportService.ts`, `projectStorageService.ts`)
- **Универсальный импорт:** кнопка «Импорт» принимает как файлы `.xlsx` (авто-определение габаритов из Y1/Z1, чтение 19 колонок и извлечение кронштейнов), так и файлы проектов `.spectool` / `.json`.
- **Сохранение проекта:** кнопка «Сохранить» скачивает файл `.spectool` с полной моделью (чертеж, ячейки, цвета, кронштейны, настройки).
- **Тиражирование однотипных модулей:** при изменении ширины $L$ или высоты $H$ в шапке все зависимые горизонтальные профили пересчитываются на лету, а для кронштейнов достаточно сменить порядковый номер.

## 5. BOM-движок и эталонная спецификация («Модуль Жукова»)

Спецификация строго соответствует производственной форме предприятия (лист «Спецификация» из `А1187 М507_Модуль Жукова.xlsx`):
1. **Колонки A–S (19 колонок):**
   - A: Тип связи (`деталь` / `комплектующие`)
   - B: Позиция на чертеже
   - C: Тип детали (по технологической карте)
   - D: Обозначение чертежа
   - E: Наименование
   - F: Количество (шт)
   - G: Примечание
   - H: Длина хлыста / исходный габарит
   - I: Длина детали (L, мм)
   - J: Ширина детали (B, мм)
   - K: Толщина (мм)
   - L: Площадь детали (м²)
   - M: Общая площадь (м²)
   - N: Вес 1 шт (кг)
   - O: Общий вес (кг)
   - P: Материал детали
   - Q: Номер порезки
   - R: Покрытие / покраска
   - S: Производственный комментарий
2. **Цветовая дифференциация в Excel:**
   - Строки деталей окрашиваются мягким зелёным цветом (`#E2EFDA`).
   - Строки комплектующих и метизов окрашиваются синим цветом (`#D9E1F2`).

## 6. Критически важные правила сборки и среды (Gotchas)

> [!CAUTION]
> Обратите особое внимание на следующие моменты при доработке проекта:

1. **Electron Main Process ДОЛЖЕН быть CommonJS (`electron/main.cjs`):**
   - В корневом `package.json` включен `"type": "module"`.
   - В Node/Electron ESM вызов `import { app, BrowserWindow } from 'electron'` приводит к падению с ошибкой:
     `SyntaxError: The requested module 'electron' does not provide an export named 'BrowserWindow'`.
   - Поэтому главный процесс Electron изолирован в `electron/main.cjs` и использует `require('electron')`. В `package.json` поле `"main"` ссылается на `electron/main.cjs`.

2. **Переменная окружения `ELECTRON_RUN_AS_NODE`:**
   - Если вы запускаете Electron из некоторых IDE, терминалов или субагентов, в окружении может быть выставлена переменная `ELECTRON_RUN_AS_NODE=1`.
   - При наличии этой переменной Electron запускается как обычный Node.js и не открывает окна.
   - **Правило:** при запуске Electron или сборщика всегда сбрасывайте переменную:
     - PowerShell: `$env:ELECTRON_RUN_AS_NODE = $null; & "..."`
     - CMD: `cmd /c "set ELECTRON_RUN_AS_NODE=& npx.cmd electron-builder ..."`

3. **Команды PowerShell в Windows:**
   - Оболочка по умолчанию — PowerShell. Для запуска `npm`, `npx` и команд с амперсандами используйте `cmd /c "..."` во избежание проблем с политиками безопасности (`PSSecurityException`) и парсингом кавычек.

4. **GitHub репозиторий:**
   - Репозиторий проекта: `https://github.com/pururuall/Spectool`.
   - **Репозиторий строго ПРИВАТНЫЙ!** Не менять видимость на public.

## 7. Инструкции по разработке и сборке

### Запуск в режиме веб-разработки:
```bash
npm run dev
# Открывает Vite сервер на http://localhost:3000
```

### Запуск в режиме Electron Desktop:
```bash
cmd /c "set ELECTRON_RUN_AS_NODE=& npx.cmd electron ."
```

### Полная сборка релизного `.exe` (Portable):
```bash
# 1. Сборка фронтенда
cmd /c "npm run build"

# 2. Упаковка в standalone Spectool.exe
cmd /c "set ELECTRON_RUN_AS_NODE=& npx.cmd electron-builder --win portable"
```
Результат сборки помещается в `release/Spectool.exe` (~109 МБ, полностью портативный, запускается на любом ПК с Windows x64).

### Загрузка релиза на GitHub:
```bash
cmd /c "gh release upload v1.0.0 release\Spectool.exe --clobber"
```

## 8. Принципы пользовательского интерфейса (UX Guidelines)

1. **Универсальность и свобода инженера:**
   - Не навязывать жесткую автопривязку крепежа там, где фасад нестандартный. Пользователь должен иметь возможность как применить шаблон в один клик, так и задать привязки вручную.
2. **CAD-эргономика:**
   - Переключение режимов по горячим клавишам: `L` — Чертить, `V` — Выбор, `O` — ORTHO, `Delete` / `Backspace` — Удаление выбранного.
   - Визуальная подсветка магнитных привязок (зелёные и голубые маркеры точек и линий).
3. **Персистентность (LocalStorage):**
   - Пользовательские шаблоны ячеек, настройки баз данных и привязанные файлы должны сохраняться в `localStorage`, чтобы при закрытии и повторном запуске приложения работа продолжалась без потери контекста.
